# 인수 검수 기준

이 파일과 cases.json은 **검수 설계**다. 현재 앱 코드가 없으므로 앱 사례의 상태는 모두 NOT_RUN이다.

## 필수 게이트

P0 사례는 데이터·예산·추천·근거·API·화면·보안·파서까지 모두 통과해야 한다. cases.json의 id는 TEST_REPORT와 AGENT_STATUS에 그대로 사용한다. 기대 결과의 의미를 바꾸려면 명세 충돌 여부를 기록하고 사용자 결정이 필요한 변경을 요청한다.

정상 경로 1개만 보이는 시연은 완료가 아니다. 빈 결과·정보 부족·외부 실패·응답 순서 역전·저장 삭제를 함께 확인한다. 기능 단위 테스트만으로 브라우저 검수나 실연동을 대체하지 않는다.

## 자연어 평가

parse_cases.json의 30개 문장에서 expected_fields의 지정 필드만 평가한다. budget.amount처럼 점 경로로 비교하며, 누락·잘못된 값은 0점, 정확한 값은 1점이다. null은 미확정으로 남겨야 하는 정답이다. 배열은 집합 동등성으로 평가한다. 총 정답 필드 수 / 지정 평가 필드 수로 산출한다.

confirmation_required_contains의 모든 필드는 확인 대상으로 표시돼야 한다. field_origin_expected에 정의된 추정 상태를 보존한다. 모호한 인원·예산 단위를 확인 없이 확정한 사례는 0건이어야 한다. 정확도 목표는 90% 이상이며 이는 프로젝트 검수 목표이지 이미 확보한 성능이 아니다.

이 30문장을 단순 문자열 키로 조회해 정답을 반환하는 구현은 금지한다. 숫자·예산·지역·시간·모호성 처리 규칙을 구현한다. 같은 의미의 변형 문장과 별도 사람이 작성한 미공개 문장으로 추가 검증한다. 규칙 기반과 LLM 기반 결과를 구분한다.

## 데이터 파생값 검증

후보별 상권 지표는 고유 area_id를 기준으로 계산한다. 같은 구역에 점포가 여러 개 있다는 이유로 비교군의 관측치를 복제하지 않는다. 백분위·가중치 재정규화·시효는 정책 파일과 일치해야 한다. 원천 집계의 결측을 0으로 보충하지 않는다.

합성 자료의 40개 점포는 추천 후보이고 가맹점 수 집계는 별도 가상 관측 모집단이다. 이를 개별 점포 매출이나 실제 카드 이용 자료로 설명하면 실패다.

## 수동 UI 검수

뷰포트 360/390/768/1280px, 키보드만의 흐름, 포커스, 폼 label, 오류, 로딩, 빈 결과를 확인한다. 지도 없이도 같은 장소 정보에 접근 가능해야 한다. 모드와 시연 기준시각은 화면에서 확인 가능해야 한다. 이미지·스크린샷을 실제 실행 없이 만들어 검수 증거로 제출하지 않는다.

브라우저 실행 권한·도구가 없으면 U01~U06 검증을 NOT_RUN으로 남기고 해당 검증 환경 또는 수동 확인을 요청한다. 다른 도메인·계약 테스트는 독립 실행할 수 있지만 최종 상태는 PARTIAL_REVIEW_REQUIRED다.

## 품질 목표와 하드 게이트의 구분

예산 초과 오표시0, 근거 없는 수치0, 무근거 인원·예산 단위 확정0, 필수 테스트 통과와 UI 검수는 하드 게이트다. 성능(p95 500ms, LLM 제외)과 5명 중4명 독립 수행은 별도 품질·사용성 목표이며 미측정 시 NOT_MEASURED로 기록한다. 성능 목표를 달성했다고 미리 쓰지 않는다. 기능이 멈추는 심각한 성능 문제는 별도 장애로 보고한다.

## 보고 필드

사례 ID, 실제 명령, 실행 OS·런타임·시각, 종료 코드, PASS/FAIL/NOT_RUN/SKIP_APPROVED, 로그·스크린샷 경로, 실패 사유와 재현 절차를 기록한다. 테스트 실행이 없는 상태에서 빈 실패 목록을 통과로 해석하지 않는다.
